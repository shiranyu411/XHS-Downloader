# 后端能力与接口边界

前端重写的功能基线。

## 能力

| 能力 | 已有实现与边界 |
| --- | --- |
| 搜索和浏览 | Qt/专用 Chrome 打开实际网页，用户登录、搜索、筛选；不是独立服务端搜索 API |
| 发现链接 | 当前已加载搜索/推荐/作者发布页，或明确次数的滚动；保留 ID、完整链接与来源，不保证覆盖所有结果 |
| 输入链接 | 完整链接、分享文字、多链接去重；短链接需要明确联网解析；可以仅登记、不执行 |
| 正文信息 | 标题、文案、作者、时间、标签、类型及平台提供的互动数；缺失字段不补造 |
| 评论回复 | 一级评论、二级回复、真实 ID/回复关系；请求与 UI 策略、分页证据、暂停与明确补采 |
| 媒体 | 图片、视频、封面、Live Photo；格式/视频偏好、进度、重试、临时文件和已有记录检查 |
| 被动记录 | 仅存档开启后手动浏览产生的相关响应，不主动请求或追溯；观察记录不冒充完整采集 |
| 本地资料 | 默认或专题资料夹，来源与尝试保留；按标题/ID、状态、来源、指定集合查询 |
| 查看导出 | 离线正文/评论及历史观察；CSV、正文 TXT/Markdown、摘要、普通/完整链接；不联网补齐 |
| 执行恢复 | 范围预览、开始/继续/重试、暂停收尾、持久化作业；重启不自动续跑 |
| 访问保护 | 首次声明、单作业互斥、预算、冷却、受限停止、人工恢复确认 |
| 配置 | 目录/命名/归档/格式/类别/文案、下载器网络参数；资料夹采集参数独立，修订不清空预算或访问锁 |

正文信息由 `source/application/` 与浏览器采集器提供；评论/原始存档/恢复在 `source/collection/`；Qt 协调入口为 `source/GUI/workbench_service.py`，桌面桥接为 `source/GUI/backend.py`。

## 工作台调用面

通过 `GuiApi.workspace_command(action, payload)` 调用：

| 分类 | action |
| --- | --- |
| 查询 | `summary`、`state`、`batches`、`detail` |
| 输入 | `preview_input`、`resolve_input`、`import`、`execute_input` |
| 执行 | `preview_selection`、`execute_selection`、`submit`、`preview`、`start`、`pause` |
| 资料夹 | `create`、`load`、`update_config` |
| 整理 | `hide_preview`、`hide`、`restore_hidden` |
| 输出 | `export_preview`、`export_content`、`copy`、`export_links`、`export`、`folder`、`export_folder` |
| 访问状态 | `report_restriction`、`ack_restriction` |

- `import` 只登记，`submit` 只排队；`execute_*` 才在明确范围内提交并执行。
- 作业类型为 `comments` / `download`；运行模式为 `discover` / `comments` / `download` / `passive`，一次只运行一种。
- 执行一次选择 1–5,000 篇；列表和评论每页 50 条，筛选/整个资料夹导出不受本页限制。
- 确认令牌绑定资料夹、配置、作品和作业身份；变化后重新预览。超时不自动重发写操作。

其他 `GuiApi`：`get_state` 提供下载任务/文件进度；`get_settings` / `save_settings` 管理实际配置；`create_tasks` / `cancel_task` / `clear_finished` 管理下载；`get_history_page` / `delete_history_records` 管理下载去重记录。另有声明、剪贴板读取、目录和关于等辅助调用。

Qt 浏览器导航属于宿主，不存在 `workspace_command('search')`；当前 Qt 拒绝旧 `collection_command`。接口可能抛异常或返回 `{ok:false,error:...}`，前端需统一处理。

## 依赖与结果的区别

1. 得到链接后可以直接下载媒体，也可以采正文评论；两者不是前后置关系。已有存档可以离线查看导出。
2. 底层 `XHS.extract(download=False)` 和 CLI `--no-comments` 能只取信息/正文，但工作台没有独立的正文作业类型。
3. 下载器生成的 TXT/MD、`ExploreData.db` 不自动变成工作台正文证据；下载成功也不等于评论完整。
4. 当前发现主要返回链接/ID，未提供严格搜索结果区及完整卡片元数据契约；不能偷偷逐篇补请求填满卡片。
5. 下载类别、文案格式等主要是下载器全局参数，不是现成的逐次作业局部选项。当前没有任意内容组合的原子作业。
6. `complete_observed` 仅表示已观察分页经过验证，不表示平台所有历史/删除/不可见评论。request 可基于有效证据续页，UI 不承诺旧游标续采。
7. 已入库、已排队、已处理、去重跳过、新增文件是不同事实；下载记录不证明文件仍在本地，Range 机制不保证任意故障都能无损续传。
8. 隐藏会取消未执行作业但不删证据；恢复显示不恢复作业。归档下载列表只整理显示；删除去重记录不删文件，也不重置工作台成功作业。
9. 原始存档和导出在 `collections/<资料夹>/`；媒体/下载器文案在实际下载目录。没有统一搬迁、删除全部文件或强制重下全部成功项的桌面命令。
10. 浏览器会话与下载器身份独立；没有复制个人 Chrome Cookie 的主路径。独立 CLI/API/MCP 进程不共用 Qt 全局账号限流器。

## 兼容入口与未提供能力

- API `POST /xhs/detail`；MCP `get_detail_data` / `download_detail`：鉴权后获取单篇信息或下载，不是完整搜索/评论管理 API。
- 图片序号下载、持续剪贴板监听、外部脚本推送主要留在兼容入口；当前 Qt 部分明确禁用。
- 用户脚本另有收藏/点赞/专辑/用户链接提取，不是工作台现成批量接口。
- CLI 支持链接文件导入、可选正文/媒体、被动记录、doctor、审计和派生报告修复。
- 未提供 XLSX、跨资料夹全文搜索、任意字段筛选、内容分析、统一结果打包或独立桌面安装包。
